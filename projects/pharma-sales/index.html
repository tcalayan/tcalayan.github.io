What Drives Pharmacy Sales? A SQL Analysis of Drug Sales, Seasons, Weather, and Search Trends

Tyra Calayan · SQL (SQLite) portfolio project

SummaryDataCleaningQ1 Top sellersQ2 GrowthQ3 Top 3Q4 SeasonsWeather & searchesLimitations

Summary

  • Pain and fever drugs (paracetamol & metamizole-type) make up about half of all sales (49.3%). Pain and anti-inflammatory drugs together make up about 70%.
  • Respiratory (airway) and allergy drugs are the growth story. Airway drugs about doubled from 2014 to 2018 and held the #3 spot from 2016 to 2019.
  • Three classes are strongly seasonal: antihistamines peak in spring, while pain/fever and airway drugs peak in winter.
  • Outside signals track sales for seasonal drugs. Antihistamine sales follow allergy searches and warm weather; pain/fever and airway sales follow cold weather. These links held even after removing long-term trends.
  • Searches don't predict prescription drugs like anxiolytics and sedatives.

About the data

  • Sales: Kaggle “Pharma sales data”: monthly sales from one pharmacy in Serbia (Niš), Jan 2014 – Oct 2019, for 8 drug classes (ATC codes).
  • Why Serbian data? Public pharmacy sales data for the Philippines isn't available, so this is used as a proxy to show the methods.
  • Google Trends (Serbia, monthly): 6 search terms, each downloaded separately (each has its own 0–100 scale).
  • Weather (Open-Meteo Historical API): daily weather for Niš, aggregated to monthly.
  • Tool: SQLite (DB Browser for SQLite)

Section 5 · Q4

Do sales change with the seasons?

Why it matters Seasonal patterns help with stock planning and ad timing.

Method note: Serbia is in the Northern Hemisphere (winter = Dec–Feb). pct_vs_drug_avg compares each season to that drug's own average, so big and small sellers can be compared fairly. All years are pooled to show the typical yearly cycle.

Show SQL
-- Q4: Seasonal pattern per drug class
WITH seasonal AS (
  SELECT
    d.drug_class,
    CASE
      WHEN strftime('%m', s.datum) IN ('12', '01', '02') THEN 'Winter'
      WHEN strftime('%m', s.datum) IN ('03', '04', '05') THEN 'Spring'
      WHEN strftime('%m', s.datum) IN ('06', '07', '08') THEN 'Summer'
      ELSE 'Autumn'
    END AS season,
    AVG(s.units_sold) AS avg_monthly_units
  FROM sales_clean AS s
  JOIN drug_names AS d
    ON s.atc_code = d.atc_code
  GROUP BY d.drug_class, season
)
SELECT
  drug_class,
  season,
  ROUND(avg_monthly_units, 1) AS avg_monthly_units,
  ROUND(100.0 * (avg_monthly_units - AVG(avg_monthly_units) OVER (PARTITION BY drug_class))
        / AVG(avg_monthly_units) OVER (PARTITION BY drug_class), 1) AS pct_vs_drug_avg
FROM seasonal
ORDER BY drug_class,
  CASE season WHEN 'Winter' THEN 1 WHEN 'Spring' THEN 2 WHEN 'Summer' THEN 3 ELSE 4 END;

Step 3: Join sales + searches + weather

Show SQL
-- Combine sales + Google Trends + weather (one row per month per drug class)
CREATE VIEW sales_covariates AS
SELECT
  substr(s.datum, 1, 7) AS month,
  s.atc_code,
  d.drug_class,
  s.units_sold,
  CASE s.atc_code
    WHEN 'M01AB' THEN t.sciatica
    WHEN 'M01AE' THEN t.sciatica
    WHEN 'N02BA' THEN t.flu
    WHEN 'N02BE' THEN t.flu
    WHEN 'N05B'  THEN t.anxiety
    WHEN 'N05C'  THEN t.insomnia
    WHEN 'R03'   THEN t.asthma
    WHEN 'R06'   THEN t.allergy

  w.avg_temp,
  w.total_precip_mm,
  w.avg_sunshine_hrs
FROM sales_clean AS s

JOIN weather_monthly AS w ON substr(s.datum, 1, 7) = w.month;

Step 4: Correlation (raw values)

What is correlation (r)?

  • r runs from −1 to +1. Near +1 = rise and fall together. Near 0 = no clear link. Near −1 = one goes up when the other goes down.
  • With ~66–68 months, |r| above about 0.24 is unlikely to be pure chance (rule of thumb: 2 ÷ √n). Treat 0.25–0.30 as borderline; 0.4+ is more convincing.
  • SQLite has no built-in correlation function, so it's calculated with the standard Pearson formula.
Show SQL
-- Correlation of monthly sales with matching search interest and temperature
WITH stats AS (
  SELECT
    drug_class,
    COUNT(*)                               AS n,
    SUM(units_sold)                        AS sx,
    SUM(units_sold * units_sold)           AS sxx,
    SUM(search_interest)                   AS sy,
    SUM(search_interest * search_interest) AS syy,
    SUM(units_sold * search_interest)      AS sxy,
    SUM(avg_temp)                          AS st,
    SUM(avg_temp * avg_temp)               AS stt,
    SUM(units_sold * avg_temp)             AS sxt
  FROM sales_covariates
  GROUP BY drug_class
)
SELECT
  drug_class,
  n,
  ROUND((n * sxy - sx * sy) / SQRT((n * sxx - sx * sx) * (n * syy - sy * sy)), 2) AS r_search,
  ROUND((n * sxt - sx * st) / SQRT((n * sxx - sx * sx) * (n * stt - st * st)), 2) AS r_temp
FROM stats
ORDER BY drug_class;

Step 5: Correlation (month-to-month changes)

Raw values can look linked just because both rise over the years (e.g., more people using Google). Comparing changes (“sales went up this month; did searches go up too?”) removes those long-term trends. Feb 2017 is skipped because its previous month (Jan 2017) is missing; the first month is skipped because it has nothing to compare to. So n = 66.

-- Correlation using month-to-month changes (removes long-term trends)
WITH changes AS (
  SELECT
    drug_class,
    month,
    LAG(month) OVER w                             AS prev_month,
    units_sold      - LAG(units_sold) OVER w      AS d_sales,
    search_interest - LAG(search_interest) OVER w AS d_search,
    avg_temp        - LAG(avg_temp) OVER w        AS d_temp
  FROM sales_covariates
  WINDOW w AS (PARTITION BY drug_class ORDER BY month)
),
clean AS (
  SELECT *
  FROM changes
  WHERE prev_month IS NOT NULL
    AND date(prev_month || '-01', '+1 month') = month || '-01'
),
stats AS (
  SELECT
    drug_class,
    COUNT(*)                  AS n,
    SUM(d_sales)              AS sx,
    SUM(d_sales * d_sales)    AS sxx,
    SUM(d_search)             AS sy,
    SUM(d_search * d_search)  AS syy,
    SUM(d_sales * d_search)   AS sxy,
    SUM(d_temp)               AS st,
    SUM(d_temp * d_temp)      AS stt,
    SUM(d_sales * d_temp)     AS sxt
  FROM clean
  GROUP BY drug_class
)
SELECT
  drug_class,
  n,
  ROUND((n * sxy - sx * sy) / SQRT((n * sxx - sx * sx) * (n * syy - sy * sy)), 2) AS r_search_change,
  ROUND((n * sxt - sx * st) / SQRT((n * sxx - sx * sx) * (n * stt - st * st)), 2) AS r_temp_change
FROM stats
ORDER BY drug_class;

What it means

  • Antihistamines follow allergy searches and warm weather, even after removing trends.
  • Paracetamol & metamizole and airway drugs sell more when it's cold. For paracetamol & metamizole, temperature is a better signal than flu searches.
  • Diclofenac-type follows Sciatica searches month to month (the link got stronger after removing trends).
  • Prescription drugs (anxiolytics, sedatives) don't follow searches, which makes sense since they need a doctor's prescription.
  • Business use: for seasonal drug classes, weather and search data could help plan stock and time ads.

Section 7

Limitations

  • One pharmacy in Serbia, used as a proxy since public Philippine pharmacy sales data isn't available. Results show methods, not the Philippine market.
  • Data is from 2014–2019, so findings aren't current market trends.
  • Excluded months: Oct 2019 (partial) and Jan 2017 (missing, 1 unit recorded).
  • 2017 was lower for all classes, likely a store-level issue the data can't explain.
  • 2019 covers Jan–Sep only, which can skew yearly averages for seasonal drugs.
  • Correlation is not causation. Temperature and searches are both seasonal, so part of the links may reflect seasons in general.
  • Google Trends values are relative (0–100 per term), not search counts. Terms were downloaded separately and are never compared with each other.
  • Sunshine data is model-based and likely overestimated, so it was not used.
  • The rough significance cutoff (|r| ≈ 0.24) assumes independent months; real monthly data is somewhat linked month to month, so borderline values should be read with care.
